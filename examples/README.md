# Examples

Prelum owns no templates: every render carries its own source. These files show the shape of a
request rather than a template library the service resolves by name.

- `hello.typ` — the `source` a caller sends, with `lib/label.typ` as its one
  auxiliary file.
- `lib/label.typ` — that auxiliary file; the key in `files` is the path the source imports.
- `render-request.json` — the two of them assembled into a request body. It is generated from the
  two `.typ` files by `uv run python scripts/regenerate-example-request.py`;
  `tests/test_examples.py` fails if they drift.

The three directories beside them are the templates published on the
[documentation site](https://vrtfinland.github.io/prelum/examples/):

- `invoice/` — an A4 invoice that computes its totals from `data`.
- `label/` — an 80x50 mm asset label.
- `report/` — a three-page report, which is also the multi-page archive example.
- `manual/` — the documentation site itself, typeset as a PDF. Its `data` is generated by
  `scripts/manual_content.py` from `docs/` and `mkdocs.yml`; the logo and the four font cuts under
  `manual/fonts/` travel in `files`, which is what lets the manual look the same wherever it is
  built. Inter Display sets the name on the cover and Space Grotesk sets the headings, matching the
  documentation site. Both are SIL OFL 1.1, with their licences beside them.

The first three hold `main.typ` and the `data.json` they are rendered with; the manual builds its
data instead. The published PDF, PNG and SVG files under `docs/examples/` are generated by
`make docs-build` and are not committed.

```bash
curl -X POST http://localhost:9870/v1/render \
  -H "content-type: application/json" \
  -H "X-Prelum-Api-Token: dev-only-insecure-token" \
  -d @examples/render-request.json > hello.pdf
```
